Why Cadenza over QWERTY?

Problem with QWERTYCadenza solution
High same-finger bigrams (ed, ce…)Colemak-DH distributes load evenly across all fingers
Common letters on weak fingersAll 5 most-frequent English letters (E T A O I) on home row
Lateral stretch for B, Y, HColemak-DH minimises lateral movement
Ctrl/Shift require leaving home rowHold A=⌘ · S=⌃ · T=⇧ — no finger leaves home
Number row forces arm travelDedicated L5 on thumb hold — zero arm movement
Symbol keys scattered far from homeAll symbols via L4/L5/L8/L9 from home position
Wide keyboard forces arms apartCorne Choc split form aligns with natural shoulder width

Colemak reduces finger travel by 50–70% compared to QWERTY for typical English text.

Design Principles

  1. Home position first — every frequent key reachable without wrist movement
  2. Symmetric layer access — L7/L8/L9 reachable from either hand
  3. Unified numpad grid — same shape for symbols (L4), numbers (L5), F-keys (L6)
  4. Finger-tuned timing — tipping terms match natural speed per finger
  5. Tap = primary, Hold = secondary — consistent throughout
  6. Macros earn their slot — only genuinely complex multi-character sequences qualify
  7. Vial-native — all settings editable without a firmware rebuild

Key Design Decisions

Vial-native constraint — deliberate macro limit

Cadenza stays within Vial's 16 macro slots so that the entire layout is editable in the standard Vial desktop app without any custom firmware build. Increasing the macro count requires recompiling QMK from source; the resulting .vil file only restores correctly on keyboards running that exact custom firmware, breaking portability. This constraint shaped the Code & CLI layer: only sequences with genuinely mixed shifted characters earn a slot. Simple repeated characters like || and && do not qualify — they are just the same key pressed twice.

L9 access — middle finger down vs index finger sideways

The Code & CLI layer is triggered by holding C (left) or , (right) — middle finger moving straight down one row. The alternative was G or M (index finger stretching laterally to the inner column). Middle finger was chosen because vertical movement along a finger's natural axis is shorter, more natural, and does not destabilize the hand. The index finger anchors the hand's lateral position; moving it inward shifts the entire hand. G and M retain their tap=letter · hold=App/Menu assignment unchanged.

TD(3) — removing the ~/ double-tap from the / key

In v0.6.1, the / key had a double-tap that fired the ~/ macro. This caused false triggers when typing :// in URLs — two rapid slashes activated the macro unintentionally. The fix: remove the double-tap from / entirely (TD(1) is now tap=/ · hold=MO(7) only) and introduce TD(3) on the L9 middle finger position. TD(3) gives tap=~/ and double-tap=../, which is also chainable — repeated double-taps while holding the layer key build ../../ etc. without re-entering the layer.

L8 Bracket Pairs Hold D or Hold H

All four bracket pairs as tap/hold Tap Dance keys, mirrored on both halves. Tap = open · Hold = close.

The arrangement is mirrored, not reversed: the same finger reaches the same bracket regardless of which hand holds the layer key — index finger = (, middle = [, ring = <, pinky = {.

Double-tap produces the same closing bracket as hold. This is by design — two ways to close: hold for open-then-close in one motion, or tap-then-double-tap as a distinct gesture for each bracket.

Four keys on both home rows — mirrored so either hand reaches every sequence. The same finger on either hand reaches the same sequence. Hold C or , to activate from either side.

Cadenza uses 10 of 16 available Vial macro slots (M0–M9). Six slots remain free. The 16-slot limit is a deliberate constraint — staying within standard Vial firmware keeps the layout portable and editable without any build toolchain.
